# 资源入口与工具

rDevTool 的 **资源入口** 是工作区里用于“快速找到并打开目标，或启动一条受控流程”的统一入口。它既可以保存一个网站、目录或文件，也可以引用 Action、Link、Workflow、网页动作或项目运行能力。

这篇文档回答五个问题：

1. 资源入口页面如何查找和打开内容。
2. 网站、目录、文件、应用和脚本分别应该怎么配置。
3. 工具入口中的 Link、Action、Workflow、网页动作和 Runtime 有什么区别。
4. 资源入口怎样和项目的运行面板、启动档案、代理联动。
5. 遇到“待补”、入口消失或工具无法执行时应该检查什么。

## 1. 先理解资源入口的结构

一个入口由以下信息组成：

| 信息 | 作用 | 示例 |
| --- | --- | --- |
| 配置源 | 决定入口从哪份配置加载和保存 | 默认配置、工作区配置、团队配置 |
| 分类 | 让入口按项目、资料、自动化或外部系统分组 | 项目入口、设计资料、联调入口 |
| 名称 | 页面上显示给人的名称 | 测试环境、需求目录、启动项目 |
| 类型 | 决定点击后的默认行为 | 网站、目录、文件、应用、脚本、工具 |
| 目标 | 入口实际指向的 URL、路径、Bundle ID、脚本或工具 Key | `https://...`、`/Users/...`、`workspace-start-check` |
| 动作 | 工具入口点击时采用的动作 | 查看计划、执行、检查配置、启动项目 |
| 备注 | 解释用途和使用边界 | 联调入口、只读资料、需要代理 |

资源入口只保存“如何找到目标”的配置。入口引用的底层定义仍然由对应模块维护：

- Action 的参数 Schema 和执行器来自当前配置源的 `actions.toml`。
- 网页动作的脚本、受控页面和调试设置在项目运行面板的 **网页动作** 中维护。
- Runtime 指向项目和启动能力，项目命令、启动档案和运行环境在项目配置与运行面板中维护。
- Link 的步骤定义在 Link 配置中维护，资源入口只负责引用 Link Key 和默认查看计划的动作。

因此，删除一个入口通常只会移除快捷入口，不会删除它引用的 Action、Link、网页动作或项目。

## 2. 进入资源入口页面

从左侧打开 **资源入口**。页面通常包含以下区域：

1. **配置源上下文**：显示当前正在读取的配置来源，以及配置文件位置或链路状态。
2. **搜索框**：搜索入口名称、类型、URL、路径、备注、脚本、工具 Key 和动作。
3. **类型筛选**：`全部`、`网站`、`目录`、`文件`、`工具`。
4. **分类标签**：按分类查看入口，并显示每个分类的数量。
5. **入口卡片**：展示名称、类型、分类、备注、目标摘要和打开/执行按钮。
6. **配置入口**：打开 **资源入口配置**，新增、编辑、复制或删除入口。

搜索同时匹配分类名称、入口名称、目标摘要、备注、运行环境、路径、脚本、工具 Key 和工具动作。没有搜索词时，页面优先显示当前分类；输入搜索词后会在全部分类中查找。

按下 `Enter` 会打开或执行第一个匹配入口。对于会产生副作用的工具，不要把“第一个结果”当成确认；执行前仍然要在 Action、Link 或运行面板中核对实际目标。

### 2.1 页面上的按钮含义

| 按钮或状态 | 含义 |
| --- | --- |
| 外部打开图标 | 打开网站、目录、文件或应用目标 |
| 播放/运行 | 启动脚本、Link、Runtime 或网页动作 |
| 闪电/参数 | 打开参数化 Action 的表单和确认流程 |
| 计划 | 只读取 Link 或动作配置，查看预计步骤和目标 |
| `可用` | 入口的必要字段已经配置，目标可以继续处理 |
| `待补` | 缺少 URL、路径、Bundle ID、脚本或工具 Key 等必要信息 |
| 配置源状态 | 当前配置可读、只读、缺少能力或存在外部变更 |

网站、目录、文件和应用通常是直接打开；脚本、工具和 Action 可能启动进程、访问网页、操作代理或控制项目运行，使用前应看清动作和确认提示。

## 3. 配置资源入口

点击资源入口页面的配置按钮，打开 **资源入口配置**。弹窗左侧是入口列表，右侧是当前条目的编辑器。

列表和编辑器采用与项目配置、代理配置一致的弹窗布局：左侧列表独立滚动，搜索和类型筛选与列表项保持同一内边距，右侧顶部标识当前入口，底部使用统一的固定操作栏。入口较多时只滚动列表区域，滚动条保持窄体；亮色和暗色主题共用选中态、边框和主按钮语义色，避免切换配置源或编辑条目时出现不同的交互风格。

### 3.1 选择配置源

顶部的 **配置源** 决定本次编辑读取和保存哪份入口配置。切换之前先处理当前草稿：

1. 保存当前修改，或关闭并放弃草稿。
2. 确认配置源名称、文件路径和可用能力。
3. 切换后等待入口、Action、网页动作和项目列表重新加载。
4. 如果配置源是只读或不支持资源链路，页面会保留查看能力，但不能直接保存。

页面显示的配置源是事实来源。遇到“本机有这个入口，但页面没有”时，优先检查是不是打开了另一份配置文件。

### 3.2 新增和编辑

常用操作顺序：

1. 选择一个分类，或点击 **新增分类** 建立新的分组。
2. 点击 **新增**，选择入口类型。
3. 填写名称、目标和备注；工具还需要选择工具类型、Key 和动作。
4. 检查右侧的状态提示和目标摘要。
5. 点击弹窗底部 **保存**，等待页面出现“已保存资源入口配置”。
6. 回到资源入口页面，确认分类数量和入口卡片已经刷新。

编辑器中的临时修改不会立即写入配置文件。使用 Link 向导保存 Link 定义后，还要再次保存资源入口本身，才能让入口引用生效。

### 3.3 复制和删除

- **复制**适合创建同类环境入口。复制后要立即修改名称、URL、路径或 Key，避免两个入口指向同一目标却让使用者误判。
- **删除**只删除当前配置中的入口记录。它不会删除目录、项目、脚本文件，也不会删除被引用的 Action、Link 或网页动作定义。
- 工作区配置中的系统生成入口，例如资料目录和工作日志，不应当通过普通入口删除；它们由工作区配置中的目录和日志字段维护。

## 4. 网站入口

网站入口用于打开环境地址、设计稿、接口页面、项目文档、测试页面或外部系统。

### 4.1 必填和可选字段

| 字段 | 说明 |
| --- | --- |
| 名称 | 页面显示名称，建议包含环境或用途，例如“联调审核页” |
| 类型 | 选择 `网站` |
| 所属分类 | 让同类入口集中显示 |
| URL | 要打开的完整网址，建议包含协议和必要的固定查询参数 |
| 运行环境 | 可选的 Runtime Profile；只有需要固定浏览器、代理或 Host 规则时再填写 |
| 浏览器 | 当前 Chrome、系统默认、Google Chrome、Microsoft Edge、Brave Browser 或自定义应用 |
| Profile | 指定浏览器 Profile，例如 `Default` 或 `Profile 2` |
| 备注 | 记录用途、访问前置条件和只读/可写边界 |

### 4.2 浏览器选项怎么选

- **当前 Chrome**：复用当前已登录的 Chrome 会话，适合日常查看和需要现有登录态的页面。
- **系统默认**：交给系统处理 URL，不指定浏览器 Profile。
- **指定浏览器**：需要固定使用 Chrome、Edge 或 Brave 时选择对应浏览器。
- **Profile**：只有在指定浏览器支持 Profile 时填写。不要把浏览器登录数据目录复制到入口备注或仓库。
- **运行环境**：它不是浏览器 Profile，而是更完整的 Runtime Profile，可以同时提供代理、Host 解析、CDP 和网页动作能力。

如果只是打开一个地址，不必为了“看起来完整”配置 Runtime Profile。只有当页面依赖特定网络、代理、浏览器调试或网页动作时，才把运行环境与网站入口关联起来。

### 4.3 网站入口的安全边界

- URL 中不要写入 token、Cookie、Authorization 或临时签名，尤其不要把带敏感查询参数的地址提交到共享配置。
- 需要登录的页面优先使用当前浏览器会话或本机私有配置。
- 打开成功只代表浏览器接受了 URL，不代表页面业务状态或权限检查成功。
- 需要自动点击、提交或验证页面时，使用网页动作或运行面板，不要把复杂脚本塞进普通 URL。

## 5. 目录、文件和应用入口

### 5.1 目录入口

目录入口适合放需求资料、设计稿目录、项目仓库、构建产物、日志目录和本地工具目录。

填写 **目录路径** 后，可以使用文件夹选择器确认路径。建议：

1. 使用当前机器上稳定存在的绝对路径。
2. 名称写清资料用途，不只写 `temp`、`test` 或 `folder`。
3. 备注中说明这是项目目录、资料目录还是构建产物目录。
4. 共享配置不要写入只在个人电脑存在的路径，或者要在备注中说明它是本机路径。

目录入口打开的是文件管理器中的目录。它不会自动把目录注册成项目，也不会改变工作区的项目实例目录。

### 5.2 文件入口

文件入口适合工作日志、需求文档、配置样例、构建报告和固定模板。填写 **文件路径** 后，应用会按系统默认方式打开文件。

目录与文件要区分：目录用于浏览一组资料，文件用于直接打开一个固定文档。不要把需要运行的脚本只配置成文件入口；脚本应使用脚本类型，才能显示工作目录和执行行为。

### 5.3 应用入口

应用入口通过 Bundle ID 和应用名称定位本机应用，适合打开 Finder、浏览器、终端或团队工具。应用入口只负责启动或唤起应用，不负责向应用传入复杂参数；需要参数化执行时使用脚本或 Action。

## 6. 脚本入口

脚本入口用于打开或启动一个已经存在的本地脚本。配置时至少确认：

- **脚本路径**指向当前机器可读的文件。
- **工作目录**包含脚本需要的相对路径和依赖。
- 脚本的参数、环境变量和退出码约定已经写在脚本或对应 Action 定义中。

简单的个人脚本可以使用脚本入口。脚本需要项目选择、分支、环境、计划、日志、取消或结构化结果时，应封装成 Action。这样使用者能在界面中看到执行范围，也能在 Record 中复核结果。

脚本不会自动获得当前工作区或当前项目上下文。需要这些上下文时，优先使用 Action、Runtime 或 Link 的受控能力，不要依赖“当前终端目录”这类隐式状态。

## 7. 工具入口类型

选择类型为 **工具** 后，编辑器会要求填写工具类型、引用 Key 和动作。当前内置类型如下：

| 工具类型 | 适合做什么 | 常见动作 | 定义维护位置 |
| --- | --- | --- | --- |
| `Link` | 把准备、代理、项目启动、页面打开和检查串成联调链 | 查看计划 | Link 配置/Link 向导 |
| `参数化 Action` | 用 Schema 生成参数表单并执行受控任务 | 执行动作、检查配置 | 当前配置源的 `actions.toml` |
| `Workflow` | 作为自动化、回放或规则的入口 | 查看计划、打开配置 | 对应 workflow、replay 或 rule 配置 |
| `网页动作入口` | 引用运行面板中已经定义的网页动作 | 打开目标、执行动作、检查配置 | 项目运行面板的网页动作 |
| `Runtime` | 指向一个项目的启动、聚焦、检查或停止能力 | 检查配置、启动、唤起、停止 | 项目配置和启动档案 |

工具入口的 Key 是引用关系，不是显示名称。Key 不存在时，入口可以保留在配置中，但页面会显示警告或“待补”，不能假设执行会成功。

### 7.1 Link：联调流程入口

Link 适合描述一条可预览的联调链。例如：

1. 检查项目目录和依赖。
2. 启动或检查本地代理。
3. 选择项目启动档案并启动项目。
4. 打开目标网页或当前浏览器页面。
5. 执行 Ready、HTTP 或网页动作检查。

资源入口中的 Link 默认动作是 **查看计划**。使用 Link 向导编辑或新建 Link 时，先确认步骤顺序、项目、代理和运行环境；保存 Link 定义后，回到资源入口配置中保存引用。

查看计划只解析步骤，不代表项目已经启动、代理已经监听或网页动作已经执行。计划通过后仍要根据步骤的副作用逐项确认。

### 7.2 参数化 Action：带 Schema 的动作

Action 适合批量构建、部署、分支处理、环境检查和需要固定参数的本地任务。入口会从当前配置源加载 Action 定义，并根据 Schema 生成参数表单。

使用顺序：

1. 在工具类型中选择 **参数化 Action**。
2. 选择已有 Action Key，检查参数数量和 Action 名称。
3. 先执行 **检查配置** 或打开 Action 计划，确认工作区、项目、分支、环境和写入范围。
4. 必要时再选择 **执行动作**，在确认前重新检查参数。
5. 执行结束后查看运行日志、结果链接和 Record。

固定上下文可能不能在入口中覆盖。不要把共享 Action 当作个人脚本使用；需要改变 Action 行为时，应修改定义或创建一个新的 Key。

### 7.3 Workflow：自动化流程入口

Workflow 入口用于保存 workflow、replay 或 rule 标识，适合把一个已有自动化流程放到工作区中快速定位。当前资源入口首期支持 **查看计划** 和 **打开配置**，主要用于发现和预览，不把未确认的自动化流程直接当作普通按钮执行。

如果流程最终会触发构建、推送、部署或网页写入，使用者仍需要进入对应模块确认实际目标和授权边界。

### 7.4 网页动作入口

网页动作入口只引用已有的网页动作，不在资源入口里维护脚本和受控页面。

- **打开目标**：定位到动作配置或目标页面。
- **检查配置**：查看动作类型、参数和受控链路是否可用。
- **执行动作**：在当前受控浏览器目标上运行网页自动化，执行前应确认页面和参数。

没有可引用的网页动作时，先进入 **项目运行面板 > 网页动作** 创建或检查动作。运行面板负责页面目标、CDP、浏览器 Profile、参数和结果；资源入口只是把这个动作放到当前工作区中。

### 7.5 Runtime：项目运行入口

Runtime 入口需要引用一个项目 Key，可以选择以下动作：

- **检查配置**：查看项目命令、启动档案、运行环境和预检结果。
- **启动项目**：按项目和可选 Runtime Profile 启动项目。
- **唤起页面**：聚焦运行中的项目页面或 `focusUrl`。
- **停止项目**：停止 rDevTool 管理的运行会话；外部占用必须先确认归属。

Runtime 入口适合放在某个需求工作区首页，但完整的启动参数、预检、日志和网页动作仍应在 **项目管理 > 项目 > 运行面板** 中查看。

## 8. 资源入口和运行面板的关系

可以把两者理解成不同层级：

| 层级 | 主要问题 | 适合入口 |
| --- | --- | --- |
| 资源入口 | “我要快速找到哪个页面、目录或流程？” | 网站、目录、文件、应用、脚本、工具 |
| 项目列表 | “我要对哪个项目做什么？” | 启动、停止、打开目录、选择档案 |
| 运行面板 | “这次启动最终用了什么，哪里失败了？” | 概览、运行配置、日志、网页动作 |

典型使用流程：

1. 在工作区首页或资源入口点击 Runtime、网站或 Link。
2. 如果是 Runtime，先确认引用的项目和工作区实例目录。
3. 打开项目的运行面板，查看 **概览** 中的启动链路预检。
4. 在 **运行配置** 中核对 Debug Profile、Runtime Profile、端口、代理、浏览器和 Host 规则。
5. 启动后在 **日志** 中确认命令、工作目录、PID、端口和 Ready/HTTP 状态。
6. 需要页面检查时，在 **网页动作** 中选择目标页面、动作和参数。
7. 回到资源入口继续打开资料或环境网站，或者执行下一个 Link 步骤。

![项目运行面板概览](assets/screenshots/project-runtime-panel.png)

完整的启动档案、运行配置、链路预检、日志和网页动作说明见 [项目启动与运行面板](project-runtime.md)。资源入口只负责发现和调用，不替代运行面板中的最终生效值。

## 9. 工作区范围与共享入口

资源入口会跟随当前工作区刷新。常见范围有：

- **system 全局视图**：用于查看和维护所有可用项目、共享资源和系统入口。
- **需求工作区**：只显示该需求选择的项目、资源、工具和代理。
- **工作区专属资源**：保存在当前工作区配置中，只对当前工作区生效。
- **共享入口**：来自资源配置源，可以被多个工作区选用；从工作区移除不会删除原始入口。

在全局视图中编辑共享入口时要更谨慎，因为改动可能影响多个工作区。需求只需要一个临时资料目录或联调地址时，优先创建工作区专属入口；团队长期复用的入口才放入共享配置源。

## 10. 常见问题

### 入口显示“待补”

按入口类型检查必要字段：网站看 URL，目录和文件看路径，应用看 Bundle ID/应用名称，脚本看脚本路径，工具看 Tool Key。工具 Key 如果已经填写但仍警告，检查引用的 Action、网页动作或项目是否在当前配置源中存在。

### 网站打开了错误的浏览器或没有登录态

检查浏览器选项和 Profile。需要当前登录会话时使用 **当前 Chrome**；需要固定浏览器时选择具体浏览器并填写 Profile。不要把登录数据目录复制到共享配置。

### 目录或文件在另一台电脑打不开

这是本机绝对路径不一致导致的。共享配置只能保存团队通用路径或约定变量；个人路径应放在本机配置或工作区专属配置中，并在备注中标明机器依赖。

### 工具已经保存但点击后没有动作

确认是否只保存了 Link/Action/网页动作定义，却没有再次保存资源入口。然后检查工具类型、Key、动作和当前配置源。对于 Runtime，还要确认项目存在且启动档案和目录已经补齐。

### 网页动作入口没有可选项

进入项目运行面板的 **网页动作** 创建动作并保存，再返回资源入口配置刷新。资源入口不会自动从普通网站 URL 推导网页动作。

### Runtime 显示项目可用但页面打不开

打开运行面板查看预检、最终生效端口、Ready/HTTP 验证、代理命中和 `focusUrl`。端口存在只说明有进程监听，不能证明它属于目标项目或页面已经可用。

### 资源入口页面内容和配置文件不一致

先确认当前工作区和配置源，再刷新。外部编辑配置文件前先关闭草稿；如果存在外部变更提示，使用比较或重新加载，不要用旧草稿覆盖新配置。

## 11. 使用建议

- 名称写给使用者看，Key 写给配置和引用使用；两者不要混用。
- 一个入口只承担一个清晰目标。不要把网站、脚本和运行流程塞进同一个“工具”名称。
- 普通打开用网站、目录、文件或应用；需要参数、计划、日志和 Record 时升级为 Action、Link 或 Runtime。
- 共享入口尽量不保存凭据、Cookie、私钥、临时签名 URL 和机器私有路径。
- 运行类入口优先默认“检查”或“查看计划”，确认目标后再选择启动、执行或停止。
- 每次运行后保留 Record、运行 ID、项目 Key 和有效配置来源，便于复盘和复现。
