# 工作区与工作台

rDevTool 的工作区页面是日常开发的入口。它把当前范围内的项目、资源、工具、本地代理、工作流、构建/Git 动作和运行状态放在一起，让你先确认“正在处理哪一组项目”，再开始启动、联调或执行任务。

这篇文档专门解释工作台页面和工作区配置。总手册适合按页面查找功能；项目启动的预检、运行配置、日志和网页动作请继续阅读 [项目启动与运行面板](project-runtime.md)。

## 先理解工作区范围

工作区决定页面当前可以看到和操作的范围。它不会把项目复制成另一套配置，也不会自动修改 Git 状态；它主要负责把项目、入口、代理和动作组织成一个可切换的上下文。

| 范围 | 页面表现 | 适合什么时候使用 |
| --- | --- | --- |
| `system` 全局工作区 | 汇总全部项目、共享入口和代理；配置面板以只读方式展示 | 首次配置、跨项目搜索、检查全局资源 |
| 普通工作区 | 只显示被纳入当前工作区的项目、入口、代理和动作 | 一个需求、一条联调链或一组相关项目 |
| 需求工作区 | 在普通工作区的基础上，可初始化需求目录、分支和项目副本 | 需要隔离分支、工作目录或可复现的需求环境 |

左下角工作区切换器、工作区首页卡片和配置弹窗显示的是同一套工作区数据。切换完成后，项目、资源、构建、Git、代理和活动记录都会重新按新范围加载。执行前优先核对页面上显示的工作区名称，不要只根据项目名称判断当前范围。

## 工作台首页

![工作区首页展示当前资源、工具、项目和运行状态](assets/screenshots/workspace-overview.png)

### 页面结构

工作台从上到下可以分成四层：

1. **顶部指标栏**：显示当前范围内的项目、资源、代理和 Action 数量，并提供 **工作区配置** 入口。数量用于快速判断当前范围是否完整，不代表所有项目都处于运行状态。
2. **全局搜索与类型筛选**：在 `system` 视图中可以搜索工作区、项目、入口、代理或动作，并按工作区类型筛选。搜索会同时匹配名称、Key、路径、状态、端口和动作参数。
3. **当前工作区卡片**：卡片标题显示工作区名称、类型和状态标签，摘要显示入口、项目、代理和动作数量。卡片正文按模块组织内容。
4. **工作区索引**：只有在 `system` 视图中出现，用来快速查看其他工作区的名称、类型、项目/入口数量并进入目标工作区。

### 工作区卡片里的模块

模块会根据当前工作区是否有数据自动出现。空模块不会占用页面空间。

| 模块 | 主要内容 | 常用动作 |
| --- | --- | --- |
| **入口** | 网站、目录、文件、应用、脚本等资源 | 直接打开网站、文件或目录；查看入口来源 |
| **工具** | Link、Action、Workflow、网页动作和 Runtime 工具 | 预览计划、执行动作、启动或停止联调链 |
| **项目** | 当前工作区引用的项目目录和实例状态 | 打开目录、启动/停止项目、聚焦运行页面、查看预检 |
| **本地代理** | 已绑定的 profile、监听地址、规则数和运行状态 | 启动或停止代理，进入代理配置和请求记录 |
| **工作流** | 已保存的多步骤 Action 链 | 查看步骤、启停工作流、运行或取消工作流 |
| **构建 / Git / 其他动作** | 被固定到当前工作区的批量动作 | 进入参数确认、生成计划并查看 Record |

资源入口点击后通常直接打开。工具入口会根据类型进入计划、确认或运行流程；远程写入、构建、合并和推送等动作仍然以计划、确认和 Record 为准。

### 卡片右上角操作

- **模块布局**：展开或收起当前卡片的全部模块。每个模块标题右侧也可以单独折叠；折叠状态会保存在本机，下次打开仍保持。
- **提取 AI 上下文**：生成当前工作区的结构化摘要，包括项目、入口、代理、动作和状态数量，适合复制给 AI 排查或继续任务。它是上下文导出，不会执行项目或修改配置。
- **展开/收起工作区**：暂时隐藏卡片正文，适合在 `system` 视图快速浏览多个工作区。
- **工作区索引的更多操作**：可直接提取上下文，或打开该工作区的配置面板。

### 从项目卡片启动运行时

项目行会把项目名称、实例类型、目录、启动档案和运行状态放在一起：

- **全局**：直接使用系统项目目录。
- **绑定**：工作区引用一个已有目录，目录不由 rDevTool 托管。
- **副本/托管**：工作区使用工作树或克隆目录，路径和生命周期由工作区配置维护。
- **运行中**：显示当前服务状态，可聚焦运行页面或停止服务。
- **待预检/待配置**：启动命令、目录、端口或代理仍需要处理；先打开运行来源和预检，不要重复点击启动。

启动按钮使用当前工作区的有效启动档案。运行前检查会在行内提示端口、目录、代理或依赖阻断；需要完整查看概览、运行配置、日志和网页动作时，从项目更多操作打开运行面板。

## 创建和切换工作区

### 从工作区切换器进入

1. 打开左下角当前 Workspace 切换器。
2. 选择 `system` 或一个普通/需求工作区。
3. 回到工作台后确认标题、顶部数量和项目范围已经变化。
4. 再进入项目、构建、Git 或资源页面执行操作。

如果只是想查找某个项目或入口，先在 `system` 视图搜索；如果要执行需求内的操作，切换到对应工作区后再开始。

### 新建普通工作区

在工作区首页点击 **工作区配置**，再点击左侧的 **新建工作区**。普通模式包含以下字段：

- **名称 / key**：名称用于界面显示，Key 用于 CLI、配置和稳定引用。Key 一旦被脚本或外部流程使用，不要随意更改。
- **备注 / 类型**：备注说明用途；类型用于在全局工作区索引中筛选。类型可以使用内置值，也可以创建自定义类型。
- **独立目录**：需要隔离工作目录时开启，并填写工作区目录；不启用时可以只维护范围，不创建新的项目目录。
- **资料目录**：保存工作区资料和自动生成的资源入口。默认位于工作区目录下的 `resources`。
- **复制当前配置**：以当前工作区的项目、入口和代理范围作为新工作区初始草稿，之后仍需检查路径和范围。
- **初始化工作日志 / 自动记录关键操作**：创建 `WORKLOG.md` 并决定是否记录终端和关键操作。

完成字段后点击 **创建**。新工作区会进入使用中列表；保存前未选择的项目、入口或代理不会自动进入新范围。

### 初始化需求工作区

在新建面板切换到 **需求** 模式。除名称、Key、类型和备注外，还需要填写：

- **需求号**：可选，用于把工作区和需求系统编号关联起来。
- **分支**：独立目录模式下用于创建或校验需求分支，例如 `feature-CR...`。
- **需求目录**：需求资料或工作项目录，必须先确认路径正确。
- **项目目录**：作为需求工作区基础的源项目目录，必须能识别为已配置项目。
- **项目 key**：当目录无法自动匹配项目时填写，用来明确指定项目。
- **独立目录**：开启后创建工作树/克隆等独立实例；可以在锁文件一致时复用源项目依赖，减少重复安装。

需求模式的按钮是 **初始化**。初始化前先检查预览中的项目、有效目录、分支和复制模式；如果不确定是否会创建副本，先使用 CLI 的 `--dry-run` 方案核对。

## 工作区配置弹窗

### 左侧工作区列表

配置弹窗左侧分为 **使用中** 和 **已归档** 两个标签：

- 选择使用中的工作区，右侧加载它的编辑草稿。
- 全局 `system` 工作区可以查看范围，但不能改成普通工作区或保存为可配置范围。
- 普通工作区可以点击归档；归档只隐藏它的日常入口，不等于删除项目目录或工作日志。
- 已归档工作区可以恢复；永久删除只删除工作区配置，涉及托管副本或目录时应先查看清理计划。

列表中的数字是该工作区固定动作/入口的数量提示，不是项目总数。右侧顶部的指标才用于查看项目、入口、代理、专属资源和项目实例的范围计数。

### 基本信息与目录

右侧编辑区先显示名称、类型和备注，再显示：

- **工作区目录**：需求副本、工作区资料和日志的根目录，可复制路径。
- **资料目录**：工作区专属资料和生成入口的存放位置。
- **工作日志文件**：通常是 `WORKLOG.md`。
- **自动记录关键操作**：开启后，工作区内符合条件的终端和关键操作会写入工作日志。

全局工作区会显示信息提示：它始终包含全部项目、入口和代理，下面的选择仅供查看。不要通过全局面板尝试删减范围；需要收敛范围时新建或选择普通工作区。

### 项目实例与目录关联

配置区的项目列表显示工作区当前选中的项目，以及每个项目的目录关联状态。常见操作包括：

- **创建副本**：在工作区目录下创建托管的工作树或克隆实例。
- **绑定目录**：选择一个已经存在的 checkout；该目录不自动交给 rDevTool 托管。
- **打开目录**：从页面直接检查实际生效目录。
- **修复副本**：对缺失或异常的托管实例重新检查并按提示修复。
- **解除关联**：移除工作区与该目录的绑定；涉及托管副本时先评估清理计划。

项目列表还会显示实例是否由工作区管理、目录是否健康、当前分支和有效路径。`configuredRepoPath` 是配置来源，`effectiveRepoPath` 才是当前文件操作和运行时真正使用的目录。

### 范围选择

右侧下方的范围面板分别管理 **项目**、**入口** 和 **代理**：

- 勾选 **全部** 时，工作区跟随全局配置中新加入的项目、入口或代理。
- 取消 **全部** 后，可以展开清单进行精确选择。
- 入口支持先按分类选择，再按单条入口选择；工作区专属资源不需要在这里重复勾选。
- 代理按 profile 和监听地址显示，选择后才会出现在当前工作区的本地代理模块。

修改范围只影响当前工作区的可见和可操作内容，不会删除共享配置源的原始项目、入口或代理。

## 工作区专属资源

![工作区配置中的专属资源编辑器](assets/screenshots/workspace-resource-editor.png)

专属资源只属于当前普通工作区，保存后会同步到工作区首页的 **入口** 和 **工具** 模块。它适合放需求资料、联调网址、一次性脚本和只对该需求有意义的工具。

### 添加分类和资源

1. 在 **工作区专属资源** 区域点击 **新增分类**。
2. 编辑分类名称和短标签。短标签用于首页卡片和紧凑列表，不要写过长描述。
3. 点击分类右侧的 **新增资源**，选择资源类型并填写名称。
4. 根据类型填写 URL、目录路径、文件路径、应用名/Bundle ID、脚本路径/工作目录，或工具类型、工具 Key、动作和工作目录。
5. 保存工作区配置，再回到首页确认入口数量和卡片内容。

支持的入口类型：

| 类型 | 典型字段 | 首页行为 |
| --- | --- | --- |
| 网站 | URL、浏览器、Browser Profile | 使用当前浏览器或指定 Profile 打开 |
| 目录 / 文件 | 路径 | 在系统默认应用中打开 |
| 应用 | 应用名、Bundle ID | 启动本机应用 |
| 脚本 | 脚本路径、工作目录 | 按本机脚本入口执行 |
| 工具 | Tool 类型、Tool Key、动作、工作目录 | 进入 Link、Action、Workflow、网页动作或 Runtime 流程 |

每条可编辑资源提供 **编辑、复制、删除**。复制会生成一个新的名称并打开编辑状态；删除只删除当前工作区中的这条专属入口，不会删除它引用的底层 Action、Link 或项目。

`资料目录` 和 `工作日志` 是系统生成条目。它们会显示 **系统生成** 标记，路径由上方资料目录和工作日志字段维护，不能像普通入口一样删除或编辑类型。

### 专属资源与共享入口的区别

- 专属资源保存在当前工作区配置里，只对这个工作区可见，可以直接在此新增、编辑、复制和删除。
- 共享入口来自资源配置源，在 **入口** 范围里选择加入工作区。取消勾选只会移出当前工作区，不会删除资源配置源里的原始定义。
- 如果首页同时出现同名入口，先查看分类、路径和来源标签；不要只按显示名称判断它们是否是同一条配置。

## 推荐工作流

### 开始一个需求

1. 在 `system` 视图搜索项目和已有资源，确认名称、目录和配置源。
2. 创建或进入需求工作区，确认项目范围、独立目录和分支。
3. 在工作区配置中绑定/创建项目实例，确认 `effectiveRepoPath`。
4. 增加需求资料、联调网址、代理和工具等专属资源。
5. 回到首页，先检查项目运行状态、代理状态和最近活动，再启动 Runtime 或 Link。

### 执行构建、Git 或 Action

1. 从当前工作区卡片进入构建、Git 或 Action。
2. 核对固定工作区、项目、分支、环境和参数。
3. 先生成计划或运行预检；出现阻断时按项目逐项处理。
4. 确认后执行，最后在 Record、构建链接或外部系统中确认真实结果。

### 结束需求

1. 停止不再需要的 Runtime 和代理。
2. 把已验证的启动方式、代理规则和故障结论写入知识库或工作日志。
3. 需要保留但暂时不用的工作区选择归档，不要直接永久删除。
4. 需要迁移给其他机器时，使用配置导入导出能力，并在导入计划中重新确认本机路径。

## CLI 对照

界面适合查看范围和执行有计划的操作；CLI 适合脚本化检查、审计和批量处理。

```bash
# 查看工作区列表和完整范围
rdevtool workspace list --compact
rdevtool workspace show <workspace-key>

# 创建需求工作区前先只读预览
rdevtool workspace init-demand ... --dry-run

# 在指定工作区执行一次命令，不改变应用当前工作区
rdevtool --workspace <workspace-key> <command> ...

# 添加只属于某个工作区的导航入口
rdevtool navigation add --workspace <workspace-key> ...

# 检查配置源，不直接编辑配置文件
rdevtool config-source list
rdevtool config-source show <source-id>
rdevtool config-source compare <source-id> ...
```

需求工作区的 `--copy-mode` 可以选择 `existing`、`worktree` 或 `clone`：前者绑定已有 checkout，后两者创建工作区拥有的独立实例。使用 `--dry-run` 时重点检查项目、远端身份、有效实例目录、所有权和风险提示。

## 常见问题

### 全局工作区为什么不能删减项目？

`system` 是全局视图，设计上始终包含全部项目、入口和代理。创建普通工作区后，用项目、入口和代理范围收敛内容。

### 新增资源后首页没有出现？

先确认已经点击配置弹窗底部的 **保存**，再检查资源是否保存到当前工作区而不是共享配置源。回到首页刷新后，入口和工具会按资源类型分区；工具不会出现在普通入口模块里。

### “创建副本”和“绑定目录”应该选哪个？

需要隔离分支、允许 rDevTool 管理生命周期时选创建副本；已有稳定 checkout、希望继续由自己管理目录时选绑定。选择后都要核对有效路径和当前分支。

### 页面显示的项目目录和我打开的目录不一样？

工作区可能使用托管副本或绑定目录。以项目实例卡片中的有效目录为准，配置中的源项目路径只说明配置来源，不一定是当前运行目录。

### 能否把工作区专属资源做成所有工作区都可用？

可以在资源配置源中创建共享入口，再在各工作区的 **入口** 范围中选择它。不要复制多个相同专属入口来模拟共享，否则后续修改容易分叉。

### 归档会删除资料和项目副本吗？

归档首先改变工作区配置的生命周期状态。对托管副本、资料目录和日志的清理应单独查看只读清理计划，确认没有未保存工作后再操作。

## 最后检查

每次从工作台开始任务前，快速确认以下五项：

- 当前工作区名称和类型正确。
- 项目实例的有效目录和分支正确。
- 需要的入口、代理和工具已经在当前范围内。
- Runtime、代理或工作流没有遗留的运行中状态。
- 计划、日志和 Record 能够说明这次操作的真实结果。
